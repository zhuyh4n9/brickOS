## 缩略词(abbreviations)

| 缩略词 | 英文全称 | 说明 |
|---|---|---|
| **APP** | Application | 应用(插件类别: 唯一业务逻辑, 恰一个, 不被任何插件依赖) |
| **DAG** | Directed Acyclic Graph | 有向无环图; init-DAG = 初始化依赖拓扑, 环即组合期硬错误 |
| **DMA** | Direct Memory Access | 直接内存访问(外设不经 CPU 读写内存) |
| **DoD** | Definition of Done | 完成定义(此仓库指设计阶段收敛清单) |
| **EARLY / CORE / LATE / APP** | — | 插件生命周期四相(主文档 §6.2): 关中断无线程 → 堆可用 → 服务/接口 → 进 APP main |
| **IRQ** | Interrupt Request | 中断请求(硬件中断线) |
| **semver** | semantic versioning | 语义化版本(maj.min.pat; 依赖区间语义的候选子集) |

> **编号约定**: `§6.5` = 依赖与环管理; `D1`/`D14` = 静态组合 / 二进制兼容。

## 1. 范围与现状(预留)

已有事实(散点, 待收口):

- deps 条目形状: 描述符侧 `{name, range, phase, compat_gen}`(主文档 §6.1, 已按 A-3/A-10/A-14 收口); manifest 侧 `[[dep]] = {name, range, kind, phase?}`(**不钉代**; `brickie` v0.1 §8.1); 旧写法 `{name, ">=1.0,<2.0", phase}`(§6.1 首版; §7.6 sqlite 示例 `BR_PHASE_LATE`)按新形状读
- **三类依赖**(第三类 `type` 为新增, 主文档 §6.5 原为两分): `init`(禁环, 拓扑硬错误)/ `runtime`(允许环, 经回调/注册表天然无环)/ **`type`**(仅头文件/类型可见, **不拉入运行期依赖**; `dev-core→vfs-core` 的判例, 见 `8-01` §1.3/O-S7)
- **相位单调规则**(新增, 主文档 §6.2/§6.5; `brickie` v0.1 §7.2, A-6): 对每条 `init` 边 `A → B`(A 依赖 B), 必须 `rank(complete(B)) ≤ rank(complete(A))`(`rank(EARLY)=0 < rank(CORE)=1 < rank(LATE)=2 < rank(APP)=3`)。**口径前提是"每插件两个完成点"**: ① **注册可用** = EARLY 相的 `early_init` 返回之后(`early_init` 是全体插件的回调); ② **能力可用** = 插件 `phase` 所声明相的 `init` 返回之后(仅注册型插件无 `init` 钩子, 须声明 `phase = "early"`, 此时 ② 与 ① 重合)。**声明面分工**: `[[dep]].phase` 是**依赖方的断言**(要求提供方不晚于该相完成), **提供方的自述在提供方的 `[plugin].phase`**。两条校验(缺一不可): **(R1) 完成点单调**违例 ⇒ 组合期错误 `BRV-DEP-0009`(报"B 在 A 之后完成, 但 A 依赖 B"); **(R2) 断言一致** —— 断言与提供方自述冲突(自述晚于断言)⇒ 红 `BRV-DEP-0010`。**规则只覆盖已声明 init 边**; 未声明的隐式耦合不在范围, 归符号级接口依赖扫描/静态分析。判例: `sched-coop → platform/qemu-aarch64` 两边第 ② 完成点同在 CORE ⇒ `CORE ≤ CORE` **合法, 不得误杀**
- 依赖宪法(§7.2): 单向流 / init 无环 / 共享状态唯一主人 / 符号命名空间独占
- 分类学约束(§6.3): Scheduler 恰一 / APP 恰一 / Interface 严格叶子(仅被 APP 依赖)/ 框架件间单向(cdev-core→dev-core 与 vfs-core; bdev-core→dev-core)/ 服务间可依赖(含 runtime/posix 与框架件); **APP 仅经 Interface**(删除"或直调 native", 由 `iface-min` 承接零开销路径, A-2)
- 版本区间交集校验(§6.4-1); **版本区间语义定稿**(A-5): 依赖 = (`compat_gen` **精确匹配**, `range` **固定 3 段**只比 `MAJOR.MINOR.REVISE`); `~M.m.r` ≡ `>=M.m.r,<M.(m+1).0`, `^M.m.r` ≡ `>=M.m.r,<(M+1).0.0`; `">=1.0"` ≡ `">=1.0.0"`(缺段右补 0), 4 段非法; **`COMPAT_GEN` 不进 `range`, 不能跨代比较**(字典序仅限同代内)(`brickie` v0.1 §7.4)
- **单版本政策**: 同一插件名在闭包内只允许一个版本; 多版本共存 ⇒ 组合期硬错误(关闭本篇 §3「同插件多版本共存」——**v1 明令禁止**)
- 服务时序: 发布 = 服务方 init, 查找 = 依赖方 init(3-06 §1)
- v3 动态加载: 加载期复核 api_rev/abi_id(§12)——依赖模型的前向兼容约束

## 2. 大纲(预留, 待细化)

1. **声明语义**: deps 字段/phase 含义与默认值; **自身相位声明机制 = `[plugin].phase`**(主文档 §6.2 的两完成点 + `brickie` v0.1 §8.1), `br_dep_t.phase` 收窄为断言; 本篇管 `deps × phase` 交叉(相容规则见上)
2. **版本区间**: 四段版本 + `COMPAT_GEN` 精确匹配 + `range` 3 段(缺段右补 0; 4 段非法; **不跨代比较**); 操作符集/交集算法/与 `ver[4]`、`api_rev` 的关系(等价区间式见上)
3. **init-DAG 规则**: 构建/环检测输出(报完整环路径)/相内排序 + **相位单调规则**(两条码: `BRV-DEP-0009` 完成点单调 / `BRV-DEP-0010` 断言一致; 口径前提 = 每插件两个完成点; 边界: 只覆盖已声明 init 边; `brickie` v0.1 §7.2) [执行归 3-05, 规则在本篇]
4. **分类学约束全集**: 合法依赖边清单(§6.3 表 + 依赖宪法 + `plugin_type × api_type` 的收口版本, A-1)与组合期执法形式
5. **闭包求解**: `brickie dep add`/`dep closure` 的闭包语义/单版本政策/缺失与冲突报错形态 + **`profile` 门禁**(`dev`/`release`: release 禁止依赖未冻结接口, 只作用于接口消费, 不作用于结构依赖)
6. **运行期展望**: modload(v3)对依赖模型的兼容要求
