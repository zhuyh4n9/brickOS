## 1. 范围与现状(预留)

插件 = 组合的基本单元, 布局是作者与组合器(`br`)之间的**发现契约**: 作者按约定放文件, 组合器按约定找到并校验。

已有事实(散点, 待收口):

- CLI 已暗示树内路径形态: `br add platform/qemu-aarch64 io/uart-pl011 fs/littlefs ...`(主文档 §13)——**按类别组织插件树**的读法待定稿
- 插件名 = 全局身份: 依赖声明(deps.name)/注册表/描述符 `name` 字段(§6.1)共用
- 符号纪律: `br_*` 为 core 独占; 插件自有符号带插件名前缀(§7.2 规则 4)
- 描述符物理布局: `.br_plugins` 收集段 + `__br_plugins_start/__br_plugins_stop` 边界枚举(段名三处一致: 1-01 §6.1 / 3-01 §13.3 / 3-05 §2.2); **宏形态两处矛盾待定稿**: 1-01 §6.1 展开 = 非 static `const br_plugin_t`(外部链接, 每插件导出一符号)vs 3-01 §13.3 示例 = `static const`(近零导出面, CA-10)
- 脚手架: `br new <kind>` 生成模板(4-01 §7 开放问题, 落点在本篇 §2 第 6 项)
