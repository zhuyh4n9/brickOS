## 1. 统一可打开模型(SD-1, D21 修订)

一切可打开的对象 = `br_file_t`(不透明句柄, D14)。单一原语 `br_open`, **只走挂载表**(D21 修订: 撤销裸名设备路由, 设备统一经 /dev 命名空间——Linux devtmpfs / rCore DeviceFS 同型):

- `"/"` → tmpfs(rootfs)——最短前缀兜底
- `"/dev/xxx"` → devfs——节点由 dev-core 注册表自动生成
- `"/data/xxx"` → littlefs——挂载点最长前缀匹配

```c
typedef struct br_file br_file_t;          /* 不透明(D14) */

typedef struct br_file_ops {                /* 不支持的槽位 = NULL, 返回 -ENOTSUP */
    int     (*open) (br_file_t *f, uint32_t flags);     /* D23: 会话建立 */
    ssize_t (*read) (br_file_t *f, void *buf, size_t n);
    ssize_t (*write)(br_file_t *f, const void *buf, size_t n);
    off_t   (*lseek)(br_file_t *f, off_t off, int whence);
    int     (*ioctl)(br_file_t *f, uint32_t cmd, void *arg);
    int     (*fsync)(br_file_t *f);
    int     (*poll) (br_file_t *f, uint32_t *events);   /* 查询就绪位 */
    int     (*poll_attach)(br_file_t *f, void *wait);  /* v2 预留: wait-queue 注册(NULL → -ENOTSUP, D22/D14 预留即免布局破坏) */
    int     (*close)(br_file_t *f);
} br_file_ops;

/* vfs-core 统一入口 — runtime/posix fd 表的底层原语 */
br_file_t *br_open(const char *path, uint32_t flags);
ssize_t    br_file_read (br_file_t *, void *, size_t);
ssize_t    br_file_write(br_file_t *, const void *, size_t);
int        br_file_ioctl(br_file_t *, uint32_t cmd, void *arg);
int        br_file_fsync(br_file_t *);
int        br_file_close(br_file_t *);
```

设计要点:
- **契约归属(D19)**: 本节全部 API 由 **vfs-core 插件**提供
- **治理与冻结批次**: 本节 API 面进 golden(`br-vfscore.txt`), 与 core 同一套决策记录/门禁纪律; **冻结批次 = `docs/3-os-core/3-01-core-api-list.md` §15 第四批**(非 core 组, 每文件独立升格, v1.x/M3 起)——这是依赖 vfs-core 的产品能通过 `brickie check --profile release`(禁止依赖未冻结接口)的前置
- **设备打开的内部流程(D21/D23)**: `br_open("/dev/xxx")` → 挂载表 → devfs 根 inode → `inode_ops.lookup("xxx")` → 设备节点文件 inode(**{fops, fpriv} 由类 open_file 钩子给出**)→ `fops->open` 建会话。**vfs-core 因此成为纯 VFS**(零设备知识, 依赖面收缩到 core)
- **runtime/posix 的直接受益者**: fd 表项统一持有 `br_file_t*`, 设备与文件无分别; runtime/posix 依赖 vfs-core
- 设备名命名规则: `[a-z][a-z0-9]*`, 无斜杠(devfs 节点名 = 路径分量, D21 下依旧成立)
- `br_file_t` 由 vfs-core 经 core 堆(`br_malloc`)分配, close 释放; v1 无引用计数(单 APP 无 fork)
- 独占设备(uart 类典型): 驱动在 `ops->open` 会话建立时自行返回 `-EBUSY`(独占性策略归驱动, cdev 注册契约不设 flags 载体——`8-01-device` §3)

## 2. 挂载与 ops 分层(SD-3/SD-15, D23: Linux 型四层)

```c
/* ---- 层 1: superblock 级(br_fs_ops, FS 插件注册挂载时提供) ---- */
typedef struct br_fs_ops {
    int  (*mount)(void *fs_priv, const br_fs_cfg_t *cfg, br_inode_t **root);
    void (*free_inode)(br_inode_t *ino);    /* 瞬态 inode 释放(v1 无缓存, 走查即弃) */
    int  (*unmount)(void *fs_priv);         /* v2 预留 */
    int  (*sync)(void *fs_priv);            /* 卷级 sync(对应 POSIX sync, 与文件级 fsync 并列) */
} br_fs_ops;

int br_mount_register(const char *path, const br_fs_ops *, void *fs_priv);

/* ---- 层 2: inode 级(目录 inode 操作集——路径走查与名字空间变更) ---- */
typedef struct br_inode_ops {
    br_inode_t *(*lookup)(br_inode_t *dir, const char *name);
    int  (*create) (br_inode_t *dir, const char *name, uint32_t flags, br_inode_t **out);
    int  (*unlink)(br_inode_t *dir, const char *name);
    int  (*mkdir)(br_inode_t *dir, const char *name);
    int  (*rmdir)(br_inode_t *dir, const char *name);
    int  (*rename)(br_inode_t *dir, const char *name, br_inode_t *ndir, const char *nname);
    int  (*getattr)(br_inode_t *ino, br_stat_t *st);
    int  (*setattr)(br_inode_t *ino, const br_stat_t *st);
    /* ---- 链接(2026-xx 落地, ADR-0013; 追加在**表尾** ⇒ 既有 FS 的具名初始化不受影响) ---- */
    int  (*symlink)(br_inode_t *dir, const char *name, const char *target);
    int  (*readlink)(br_inode_t *ino, char *buf, br_size_t cap);   /* 报全长, 照 POSIX */
    int  (*link)(br_inode_t *dir, const char *name, br_inode_t *target);
    /* 仍预留: mknod(设备节点经 fs/devfs 接入, D21 ⇒ 不需要它) */
} br_inode_ops;

/* ---- 层 3: file 级(每文件; open 建会话, close 销毁——D23 自 fs 级移入) ---- */
/* br_file_ops: open/read/write/lseek/ioctl/fsync/poll/close(§1) */

/* ---- 层 4: dentry 级(预留, v1 全 NULL) ---- */
typedef struct br_dentry_ops {
    int (*revalidate)(void *dentry);        /* v2: dcache 失效校验 */
    int (*compare)(void *dentry, const char *name);  /* v2: 名字比较定制 */
} br_dentry_ops;
```

**inode 对象模型**(CA-2 同型: vfs-core 公共头 + FS 私有尾):

```c
typedef struct br_inode br_inode_t;        /* 不透明(D14) */
struct br_inode {                          /* 公共头; 私有尾: littlefs=路径前缀, devfs=设备条目 */
    uint32_t type;                         /* BR_INODE_DIR / BR_INODE_FILE / BR_INODE_SYMLINK */
    const br_inode_ops *iops;              /* 目录 inode */
    const br_file_ops  *fops;              /* 文件 inode */
};
```

- **走查模型**: `br_open` → 挂载表 → 根 inode → 逐级 `inode_ops.lookup` → 文件 inode → `fops->open` 建会话; 未命中且 O_CREAT → `inode_ops.create`
- **符号链接的解析在 vfs-core**(ADR-0013): 目标可能是**绝对路径**(要重启挂载表匹配)或**相对路径**(要相对"链接所在目录"), 只有掌握挂载表与完整路径的层做得到; FS 只回答"目标串是什么"(`readlink`)。
  三条配套口径: ① 展开用**重启**而非递归(走查会被 4 KiB 栈的线程调用), 深度上界 8 ⇒ `-ELOOP`; ② **相对目标里的 `..` 不跨挂载**(有意边界, 与运行时挂载同期); ③ `O_CREAT` 撞上**悬空**链接时, 建的是**目标**(链接已存在, 建不了它自己)。
  `stat` 跟随末级链接、`lstat` 不跟随; `O_NOFOLLOW` 下末级链接 ⇒ `-ELOOP`(链接没有文件面, 不该被 open 打开)。
- **inode v1 瞬态**(SD-3 不变): inode 是走查的中间产物, `free_inode` 即弃——**有 inode ops, 无 inode cache**; littlefs 走查廉价(元数据对)、EROFS 有介质内索引, 单 APP 文件规模下 cache 是优化非需求; v2 dcache 落地时 dentry 持久化并启用 `br_dentry_ops`
- **目录枚举**: 目录 inode 的 file 面(`opendir` → `br_dir_t` 迭代), readdir 由 runtime/posix 映射
- **能力归属(D19)**: 本节契约由 **vfs-core 插件**提供(**路径走查在 vfs-core**); FS 插件实现 ops 族, manifest 声明依赖(具体 FS 见 `7-03-concrete-fs`)
- **v1 静态挂载**(SD-4): manifest → **挂载计划**(`7-03-concrete-fs` §6): fs/tmpfs → **"/" (rootfs)** 首挂 → fs/devfs → /dev → fs/littlefs → /data; **挂载点在父 FS 缺失时自动 mkdir**(静态组合便利 > 显式 mkdir 仪式); 运行时挂载(USB 热插拔): 事件模型 v2 设计, 挂载落地不早于 v3(O-S3)
- cwd 是 POSIX 概念, 归 runtime/posix; **native API 只认绝对路径**
- **链接的路径级入口**(与 `br_mkdir`/`br_unlink` 同层, ADR-0013): `br_symlink(target, path)` / `br_readlink(path, buf, cap)` / `br_link(old, new)`; 另有 `br_lstat`(不跟随末级)与 `br_fstat`(已打开句柄的属性 —— 消费者拿不到"fd 对应的路径", 而让消费者直接调 `iops->getattr` 属于越过契约)。
  `br_stat_t` 因此追加 **`nlink`**(+ `BR_STAT_NLINK` valid 位): 硬链接的可观测面("这个名字之外还有没有别的名字指向同一份数据")。错误口径: 跨挂载 `link` ⇒ `-EXDEV`; 目录 `link` ⇒ `-EPERM`; 非链接 `readlink` ⇒ `-EINVAL`; 目标串超 `BR_SYMLINK_MAX`(96) ⇒ `-ENAMETOOLONG`。
- **硬链接的数据共享在 FS**: 两个名字 → 同一个 inode → **同一份数据/同一个长度/同一个偏移基准**。tmpfs 的实现是把数据移进一个带引用计数的体(`refs` 归零才归还堆与配额); 这条属 FS 的数据模型(ADR-0013 §2.6), 不是 vfs 的契约。

## 3. poll/事件等待(SD-7 分期)

- **v1**: `file_ops.poll` 查询就绪位(`BR_POLLIN/OUT/ERR`); runtime/posix 的 `poll()` = 轮询 + `br_task_sleep` 粗粒度循环——coop 调度下语义正确且够用
- **v1 预留 / v2 实现**: `br_file_ops` 自 v1 即预留 `poll_attach` 槽位(NULL → -ENOTSUP, 与 `br_dentry_ops` 同法——D22/D14: ops 布局入 golden, 后补字段 = 布局破坏); v2 实现 wait-queue 注册与精确唤醒——**必须与 preempt 同期**(否则抢占产品上轮询延迟毛刺, 见 R-S1)

## 4. 与其他子系统的接口

### 4.1 runtime/posix(D18/D19)

- **依赖 vfs-core(D19/D21)**: open()→`br_open` 的底层原语; 设备路径经挂载表路由至 fs/devfs, 由 devfs 经 open_file 钩子接入 dev-core 侧(§4.2)
- fd 表项 = `br_file_t*`(SD-1: 设备/文件统一, fd 层零特判)
- 路径分派: **零特判**——一切经挂载表; `/dev/*` 由 devfs 承接(D21)
- errno = `-ret`(`8-01-device` §4); poll 按 §3 分期实现

### 4.2 设备接入(devfs 插件, D21)

设备不再由 vfs-core 特判路由: **fs/devfs** 插件(挂载于 /dev)把 dev-core 注册表发布为节点, 打开经 D20 子分类协议的 **open_file 钩子**(cdev-core 实现: 会话 → `br_file_t` 适配)。**vfs-core 成为纯 VFS**——零设备知识, 依赖面收缩到 core。详见 `7-03-concrete-fs` §3、`8-01-device` §2/§3。

### 4.3 page cache(无感)

page cache 以堆叠 bdev 形态存在(`7-02-bdev` §3), **VFS 与 FS 对它无感**——不需要任何配合代码。

## 6. 决策记录(本篇)

| # | 决策 | 理由 |
|---|---|---|
| SD-1 | 统一可打开模型: 一切 = `br_file_t`, `br_open` **只走挂载表**(D21 修订: 设备经 /dev 接入) | runtime/posix fd 层零特判; 单路由 = 单一语义 |
| SD-3 | handle-split VFS, v1 无 inode/dentry **cache**(D23: 有 inode **ops**, inode 瞬态) | 单 APP 文件规模下 cache 是优化非需求; 用数据再决定 |
| SD-4 | v1 静态挂载(manifest 生成配置); 运行时挂载: 事件模型 v2 设计、落地不早于 v3(O-S3) | 热插拔需要事件模型, 与 USB 栈同期 |
| SD-7 | poll 分期: v1 轮询+sleep, v2 wait-queue(与 preempt 同期) | coop 下轮询语义正确; preempt 下必须精确唤醒 |
| SD-15 | **VFS ops 分层(D23)**: super(fs 级)/inode/file/dentry(预留)四层; **路径走查在 vfs-core**(lookup 链); file_ops 增加 open(会话建立); D20 钩子演化为返回 {fops, fpriv} | Linux 型可扩展性(dcache/symlink/mountpoint 的演进路径); inode 瞬态保 SD-3 |
| **SD-16** | **符号链接与硬链接落地(2026-xx, 原型 ADR-0013)**: ① `br_inode_ops` **表尾**追加 `symlink`/`readlink`/`link`(append-only; `mknod` 仍不占位); ② **符号链接的解析在 vfs-core**(重启式展开, 深度上界 8)⇒ FS 只回答"目标串是什么"; ③ **硬链接 = 两个名字共享同一个 inode 与同一份数据**(数据归属由 FS 的数据模型决定, tmpfs 用带引用计数的体); ④ `br_stat_t` 追加 `nlink`; ⑤ 新增路径级入口 `br_symlink`/`br_readlink`/`br_link` 与 `br_lstat`/`br_fstat` | SD-15 的"演进路径"里本来就写着 symlink —— 它在 v1 就落地了(而不是 v2 预留), 因为它的**解析**必须有全局路径视野, 而这正是"走查在 vfs-core"的直接推论; 槽位 append-only 保住"既有 FS 零改动" |

## 7. 风险与开放问题(本篇)

| # | 类型 | 说明 |
|---|---|---|
| R-S1 | 风险 | poll v1 轮询在 preempt 下的延迟毛刺——v2 wait-queue 必须与 preempt 同期落地, 否则仪表类产品有可感知延迟 |
| R-S3 | 风险 | 无 inode cache 的性能上限——深路径/大目录开销需 M3 基准数据, 再决定 v2 是否引入 |
| O-S3 | 开放 | 运行时挂载/热插拔——事件模型 v2 设计(与 USB 栈联动), 挂载落地不早于 v3 |
| **O-S8** | 开放 | **相对符号链接目标里的 `..` 是否跨挂载**: v1 的实现**不跨**(走查始终在一个挂载内下推, `..` 到挂载根停住) —— 这不是 Linux 语义。做成 Linux 语义需要"挂载点感知的 `..`", 与 O-S3 的运行时挂载是同一块地基 ⇒ 建议同期收口(ADR-0013 §2.4) |
